# 향후 AI 보조 실행 검사 — v2.0 핵심 기능 후보

기록일: 2026-11-01. 확인 기준: `ef7f95d0f7a8dab2e774a7b7519f5375657ec1c9`.
상태: **사용자 아이디어 기록 / DEFERRED / 구현 NOT_STARTED**.
v2.0은 향후 제품 방향의 후보 이름이며 확정 일정·릴리스 범위가 아니다.
현재 [보강 설계](./21-goal-completion-design.md)의20개 gap·16개 순서와 첫 배포 완료 조건에
추가하지 않는다. 이번 기록으로 MCP server·감시 daemon·AI SDK·모델·API 키 설정·새 CI를 만들지 않는다.
후속 사용자 요청의 CLI 사용 Skill과 기본 MCP 연결은 보강 설계 §4.8–4.9가 별도로 소유한다.
A01은 현재 필수, A02 최소 MCP는 조건부 현재 후보이며 아래 AI 생성 코드 검사 A/B와 다르다.
기본 MCP를 구현하더라도 이 문서의 코드 생성·제출·재시도 기능까지 구현된 것으로 표시하지 않는다.

## 1. 목적과 두 단계

AI가 패키지의 API와 사용법을 바탕으로 가장 빠르고 간단한 실행 코드를 작성해,
고정 import/entry/probe만으로 도달하지 못한 사용 경로를 추가로 관찰하는 아이디어다.
사용자 AI가 대상에 관한 지식을 가졌더라도 exact version/API가 맞다고 가정하지 않는다.
생성 코드의 정상 실행과 악성 없음, 실제 위협 탐지 성능은 각각 별도로 확인한다.

| 단계 | 후보 기능 | 경계 |
| --- | --- | --- |
| A — 사용자 AI 협업 | MCP 사용에 한정해 사용자 AI가 코드 생성·한 번 수정, Heliopause가 격리 실행·관찰 | Heliopause가 자체 모델을 운영하거나 사용자 AI의 API 키를 받을 필요가 없는 초기 후보 |
| B — 자체 생성·수정 | 오픈소스/오픈웨이트 코딩 모델 내장 또는 사용자 선택 API·AI CLI 연결 | 더 큰 후속 업그레이드/v2.0 핵심 기능 후보. A와 함께 지금 구현하지 않음 |

MCP baseline: 최초 기록 당시 `PROJECT-DECISIONS.md`는 MCP 제공을 CLI 안정화 후로 두었다.
확인 기준의 `cmd/`·`internal/`·`go.mod`/`go.sum`에서는 MCP server/등록 경로를 확인하지 못했다.
MCP 등 자동화가 읽을 machine-readable 결과를 제공하는 것과 MCP server 구현 완료는 다르다.
이후 기본 연결의 채택 기준은 보강 설계 A02로 구체화했다. 여기의 A 착수 전 실제 MCP
제공 여부와 client 호환성을 별도 확인하며 현재 지원한다고 표시하지 않는다.

## 2. A의 사용자 흐름 후보

1. 사용자가 MCP에서 AI 보조 검사를 선택한다. 기본 검역은 기존 필수 검사를 유지한다.
2. Heliopause가 대상 identity/digest·exact version·지원 runtime·허용 입력·예산과 고정된
   코드 작성/디버깅 프롬프트를 사용자 AI에 전달한다. 개인 환경이나 실제 자격증명은 포함하지 않는다.
3. 사용자 AI가 짧은 실행 코드 파일을 요청 전용 전달 디렉터리에 완성해 제출한다.
   **문법·API·호출 방식의 자체 점검과 격리 환경에서의 디버깅이 필수**라는 프롬프트를 포함한다.
4. Heliopause가 완성된 제출을 확인하고 코드를 immutable snapshot으로 고정한 뒤,
   검역 대상과 함께 격리공간에서 실행한다. 기존 외부 관찰기·Inspection·Policy를 재사용한다.
5. 확인된 생성 코드 오류라면 제한된 진단과 수정 요청을 MCP 결과로 사용자 AI에 전달한다.
   재생성은 **한 번만**, 최초 제출과 수정 제출을 합쳐 **최대 두 번의 시도**로 제한한다.
   실행 전 문법/입력 검증에서 거부된 제출도 해당 시도로 계산한다.
6. 두 번째에도 생성 코드 오류로 정상 실행되지 않으면 AI 보조 검사를 종료·생략하고
   기본 검사 결과와 함께 `AI 보조 검사 실패로 생략 / 2회 시도`를 안내한다.

MCP client가 결과를 읽고 수정 코드를 다시 제출하는 흐름을 우선 후보로 둔다.
파일 이벤트만으로 사용자 AI를 자동 호출할 수 있다고 가정하지 않는다. Server가 직접
재생성을 요청하는 방식은 구현 시점의 protocol/version·client capability·사용자 제어 정책을
확인한 뒤 결정한다([MCP capability 안내](https://csharp.sdk.modelcontextprotocol.io/concepts/capabilities/capabilities.html)).
Client 중단·거절·미응답에도 대기/총시간 상한을 적용하며 몰래 AI CLI나 API를 대신 실행하지 않는다.

## 3. 프롬프트와 전달 경계

프롬프트는 짧은 코드, 실제 exact API 확인, 더미 입력만 사용, 유한 실행, 정상 종료를 요구한다.
코드 자체 점검은 필수지만 AI의 '디버깅 완료' 문장을 실제 실행 성공 증거로 인정하지 않는다.
실제 대상 import/호출·빌드·수정 확인은 Heliopause의 격리 실행 안에서만 수행한다.
호스트에서 대상 설치/실행, 새 의존성 임의 다운로드, 개인 파일·secret 접근을 지시하지 않는다.
추가 의존성이 필요하면 기존 검역 절차의 대상이며 AI 코드가 직접 보안 경계를 우회해 받지 않는다.

전달 디렉터리는 작업별로 소유·권한을 제한한다. 파일 생성 감지는 접수 계기이며 실행 권한이
아니다. 요청/세션·대상 digest·시도 번호·완성된 제출을 결합하고, 작성 중 파일·다른 요청의
파일·중복 이벤트·링크/경로 이탈·과대 파일을 거부한다. 완성 제출은 원자적인 공개 또는 명시적
제출 확인으로 구분하고, 검사와 실행은 같은 snapshot bytes를 사용한다. 재시도 파일로
횟수나 시간 제한을 초기화하지 않는다. 정확한 디렉터리/파일 형식과 MCP tool 이름은 아직 정하지 않는다.
로컬 디렉터리 전달은 client와 Heliopause가 허용된 전달 위치를 공유할 수 있어야 한다.
원격 MCP client의 파일이 로컬에 자동 생성된다고 가정하지 않으며 원격 전송은 별도 검토한다.

아티팩트 설명·주석·실행 출력과 AI 생성 코드 모두 비신뢰 입력이다. 생성 코드도 artifact와
같이 최소 권한·실제 외부망 차단·더미 자산·자원 제한 아래 실행하며 controller/Evidence를
수정할 수 없다. AI에 최종 판정·보안 설정 변경·Host shell 권한을 주지 않는다.
사용자 AI로 전달할 코드/설명/진단의 범위를 제한하고 private source·raw secret/log의 자동 전송을
금지한다. 실행 후 작업 소유 코드·workspace는 기존 자동 정리/보존 절차에 연결한다.

## 4. 두 번 실패했을 때의 정확한 의미

A는 기본 검사에 추가되는 선택 검사다. 여기서 'pass'는 **검사 통과가 아니라 생략**을 뜻한다.
기본 검사에서 ALLOW가 성립하고 필수 검사가 모두 완료됐을 때에만 기존 설치 절차를 계속할
수 있다. 결과에는 기본 판정·AI 수행 상태·시도 횟수·실패 이유·반입 결과를 분리한다.
AI 실패/생략을 탐지 성공률이나 검사 완료율의 성공 분자에 넣지 않는다.

다음은 생성 코드 실수로 뭉뚱그려 재시도/생략하지 않는다.

- 실제 악성/위반 관찰, 기본 검사 BLOCK 또는 MANUAL_REVIEW.
- 격리·관찰·증거·정리 경계의 실패, 변조·timeout 원인 불명.
- Artifact가 의도적으로 발생시킨 예외일 가능성을 배제하지 못한 실행 실패.

오류는 신뢰된 실행 결과로 분류하며 AI/Artifact의 주장만으로 '코드 실수'를 확정하지 않는다.
첫 시도에서 나온 보안 Finding을 두 번째 결과로 지우지 않는다. 생성 코드 자체의 잘못된
동작도 대상 감염으로 곧바로 단정하지 않으며, 귀속 불명은 기존 불완전/검토 정책을 따른다.
기본 필수 검사에 생긴 미완료를 선택 AI 검사의 생략으로 덮지 않는다.

## 5. B의 후속 검토 항목

내장 모델, 외부 API, 기존 AI CLI 중 필요한 방식을 평가하며 세 방식을 모두 구현하기로
확정하지 않는다. 모델/공급자·라이선스·배포 크기·CPU/GPU/메모리·속도·비용·인증정보 저장·
외부 전송 동의·생성/수정 상한·오프라인 동작을 검토한다. API 키와 모델 연결 권한은
아티팩트 실행 guest에 노출하지 않는다. 도입하면 기존 버전 단일 owner·공급 검증·
`plan → apply → verify`·유한 cache/자동 정리 체계를 재사용한다.

A/B 채택 전 동일 표본에서 기본 대비 추가 도달 경로·올바른 탐지·정상 오탐·코드 생성 실패·
미완료·시간/자원/AI 비용을 비교한다. Prompt injection과 전달 파일 교체·중복·다른 세션,
첫 보안 Finding 뒤 수정 제출·재시도 초과·안전하지 않은 fallback도 검증 대상으로 둔다.
효과가 없으면 채택하지 않으며 AI 없이도 현재 기본 검역이 완성되어야 한다.
상세 구현 설계·지원 client·수치 예산·최종 출시 버전은 후속 착수 결정 때 정한다.
