## Exact map·두 번째 검토

작은 공용 helper로 이동하고 두 실제 caller가 original verification callback과 기존 native
enrollment collaborators를 공급한다. Default non-adopt의 거부와 native UV client pin/source,
독립 authentic old wheel 비교·single-link/unknown/cross-scheme/script/cache 제한을 유지한다.
원래 body의 mapped 비교와 실제 UV pip native 소비자를 함께 검증한다.

Project preparation에 explicit adopt intent와 기존 native lookup/intake를 연결한다. Original
inventory 전체를 확인한 뒤 native destination을 **메모리상의 held prestate**에만 추가한다.
현재 선택/Policy 실패나 close만으로 HAA ownership 기록을 쓰지 않는다. New graph의 검사와
승인은 재실행하고 native 선택을 반복하지 않는다. Source/target/원본 files guard를 계속 확인한다.

Native resolver와 selected reader는 원래 여섯 controls만 받는다. Controller가 인증한 기존
`pypi-update-native-ownership.json`을 일곱 번째 immutable data control로 결합한다. 기존 proof
digest binder body를 schema 매개변수로 공용화하며 UV pip의 schema/bytes는 유지하고 project는
별도 schema를 사용한다. Proof body나 marker 자체가 approval authority가 되지 않는다.

Project cache의 공개 기본 생성자는 strict native six-control 검증을 유지한다. Promotion 내부의
proof 경로만 validated base update와 실제 held proof로 expected bound update를 재구성해 exact
original/selected/context/dependency/graph 일치를 확인한다. Stage/open 모두 이를 재검증하고
기존 current Evidence/Policy·whole archive/cache engine을 재사용한다. Physical publication은
기존 두 project files와 승인 wheel outputs만 대상으로 하며 proof는 records에 남긴다.
