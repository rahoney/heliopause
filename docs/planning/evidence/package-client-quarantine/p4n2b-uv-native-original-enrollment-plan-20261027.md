## 재사용 지도

기존 beginToolTarget의 boundary/locks/cleanup을 한 번만 사용한다. 기존 fresh/managed entry는
nil native collaborator로 같은 body를 호출한다. Native branch는 raw receipt를 보존하고
metadata·links 및 DATA interpreter snapshot을 먼저 고정한다. 원본 receipt의 Python과 target의
bin/python은 alias chain의 같은 terminal inode/bytes에 결합되어야 하며 이름만 normalize하지 않는다.

기존 WithUVLayout은 requirement/options/command set을 보존한 Host metadata projection이다.
WithUVSelectionLayout/A2 replay는 이미 fixed image Python으로 DATA만 재배치한다. Raw receipt는
별도 control로 유지한다. M1의 기존 fixed public wheel-only recipe 조건을 완화하지 않으며
옵션 부재/다른 recipe·index/local override는 이 초기 profile에서 거부한다. 일반 native default
recipe를 지원한다고 표시하지 않는다. 그 확장은 별도 acceptance 검토에 남긴다.

기존 pypiNativeEnrollment에 concrete UV tool script proof만 연결한다. 모든 original distribution의
oldWheel authentication·N2A footprint·nativeUVCacheAbsences와 prepareUVCompleteOwnership의
held prestate 설정을 재사용한다. Native receipt/RECORD/marker는 그 자체로 ownership authority가
아니다. 인증 완료 뒤 M2의 singly-owned main metadata/command/link census를 같은 검증 body로
통과시킨다. On-disk ledger·기존 ALLOW·새 승인/반입은 이 단계에서 만들지 않는다.

## 두 번째 검토와 acceptance

새 permission/role/runtime/budget·일반 native options는 추가하지 않는다. 기존 managed/fresh
경로와 complete ownership engine body를 기계적으로 대조한다. 명시 native branch만 사용할
수 있고 default unsupported/adoption required 동작은 유지한다. 독립 source proof 실패·extra/
missing/foreign command·공유/escaping links·base/runtime/metadata 변경·동시 guard·cache 등은
source 선택/ownership 승격 전에 거부하며 원본 bytes/링크와 첫 오류를 보존한다.

이 단계는 held native original 및 unapproved in-memory ownership까지 검증한다. Public backend/
current full inspection/Evidence·Policy/cache와 raw/source controls의 Manifest binding·M3 atomic
publication, CLI opt-in/실제 public native original은 N2C 이후 acceptance다. 기존 구현을 새
ownership/publisher engine으로 대체하거나 original program/Host Python을 실행하지 않는다.

adoption ACCEPTANCE_CLOSED=NO다.

기존 synthetic source ports를 재사용하여 실제 independent intake/hash/footprint 검사를
통과했다. 공개 네트워크 인증이나 실제 native tool 생성/검역은 이 결과가 아니다. Raw receipt

설정하며 on-disk ledger·기존 ALLOW·현재 승인·반입은 만들지 않았다.

Unsupported recipe·다른 interpreter/foreign link는 lookup0으로 거부했고 누락/미소유 command,
archive/script 변조와 cache, 동시 guard/base drift도 거부했다. 원본 raw bytes/metadata 부재와
실패 뒤 두 lock 해제를 확인했다. Default managed 경로의 native 거부는 유지한다.

원래 constructor/enrollment의 nil 경로, M2 layout/ownership/main-command/link body와 다섯
