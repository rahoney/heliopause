## npm implementation findings before source

Current generatedNPMProject deliberately uses file:.heliopause/artifacts/<digest>.tgz
in package.json and package-lock.json. Forwarding npm update to those controls
will not select public new versions. Preserve the public manifest/lock selection
separately from the private offline-install recipe and bind it into trusted
Manifest metadata. Publish only validated selected public controls after exact
offline output validation, using the existing transaction. Existing legacy
local-file projects need explicit bounded migration or truthful rejection; do not
infer lost version constraints or silently widen ranges.

The current npm lock parser intentionally supports a single direct root with a
complete supported transitive graph. Do not fabricate a primary or fake edges for
a multi-root project. Reuse current supported subset first and record unsupported
input before mutation; any broader project support needs complete snapshot
inspection rather than changing graph invariants.

Guard original controls/payload before resolution; explicit adoption of native
state must validate bounded ownership/path inventory and inspect the entire new
set. Existing transaction protection is already implemented and remains intact.
Detailed commands, negative cases and qualification order are owned by
[update contract](../../../user-journey-cli-ia/06-update-quarantine.md). Each lane
