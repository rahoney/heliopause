```text

필수 검사가 실패하거나 충분한 검증 근거를 확보하지 못한 경우 Artifact를 자동으로 안전하다고 판단하지 않는다. 보안에 중요한 검증 과정에서는 fail-closed를 기본 원칙으로 하며, 검사 실패·결과 불충분·판단 불가능 상태는 MANUAL REVIEW 또는 위험 수준에 따라 BLOCK으로 처리한다.
```

## D-010 검사 실패 및 불확실성 처리 확정

필수 검사가 실패하거나 충분한 검증 근거를 확보하지 못한 경우 Artifact를 자동으로 안전하다고 판단하지 않는다. 보안에 중요한 검증 과정에서는 **fail-closed**를 기본 원칙으로 한다.

| 상태 | 처리 |
| --- | --- |
| 필수 검사 실패 | `MANUAL_REVIEW` 또는 위험 수준에 따라 `BLOCK` |
| 결과 불충분 또는 판단 불가능 | 위험 수준에 따라 `MANUAL_REVIEW` 또는 `BLOCK` |
| 검사 완료 및 정책 통과 | 다음 단계 또는 `PROMOTE` 가능 |
| 위험이 발견되지 않음 | 수행된 검사 범위 안에서만 “미탐지”로 기록; 안전 보증으로 해석하지 않음 |

검사 실패와 “위험이 발견되지 않음”을 동일하게 취급하지 않는다. 결과에는 수행된 검사, 수행되지 않은 검사, 미수행 이유, 각 검사 상태, 정책 판정과 수동 검토 여부를 명확하게 기록한다.

## 사용자 원문: D-011

```text
11번: 검증 완료 Artifact 반입 및 설치
격리 환경의 설치 검사 과정에서 다운로드된 본 Artifact와 dependency는 검사에 실제 사용된 동일 Artifact를 하나의 검증 완료 세트로 승격하여, 사용자 환경과 검사 격리 환경 사이의 **검증 완료 격리 보관 영역(staging area)**으로 이동시킨다. 실제 사용자 환경에서는 가능한 한 이 영역에 보관된 로컬 Artifact 세트를 사용하여 설치한다.
승격 및 실제 설치 전에는 digest를 다시 확인하여 검사 대상과 실제 반입 대상의 동일성을 보장한다.
실제 설치 과정에서 검증 완료 세트에 존재하지 않는 새로운 dependency를 외부에서 받아야 하는 경우에는 출처·버전·digest·서명·provenance 등을 확인하고 최소한의 검사를 수행한다. 이상 징후가 발견되거나 신뢰 근거가 충분하지 않은 경우에는 해당 dependency를 다시 전체 검역 대상으로 전환한다.
Package manager가 필요 없는 독립 binary나 archive는 동일성 검증 후 사용자가 지정한 위치로 직접 반입할 수 있다.
검증 완료 격리 보관 영역 (Staging Area)
Artifact 실행 금지 설치·실행·분석을 수행하지 않고 보관과 전달만 한다.
검사 완료 Artifact만 반입 ALLOW된 Artifact와 그 dependency만 반입할 수 있다.
실제 Host 자산 접근 금지 Host Secret, 프로젝트 파일, Credential 등 실제 Host 자산을 노출하지 않는다.
Artifact 변경 금지 검증 완료 후에는 Artifact가 변경되지 않도록 가능한 한 immutable(불변)하게 관리한다.
외부 네트워크 접근 금지 보관 영역에서는 인터넷 다운로드나 외부 통신을 수행하지 않는다.
검증 기록 함께 보관 Artifact와 함께 버전, digest, 출처, dependency, 검사 결과 및 evidence를 연결하여 관리한다.
Digest 기반 동일성 유지 Staging Area로 반입할 때와 사용자 환경으로 반출할 때 digest를 확인하여, 검사한 Artifact와 실제 설치 대상이 동일함을 보장한다.
```

## D-011 검증 완료 Artifact 반입 및 설치 확정

격리 환경의 설치 검사에서 실제 사용한 본 Artifact와 dependency를 하나의 **검증 완료 세트**로 승격한다. 이 세트는 사용자 환경과 검사 격리 환경 사이의 **검증 완료 격리 보관 영역(staging area)**으로 이동하며, 실제 사용자 환경에서는 가능한 한 staging area의 로컬 Artifact 세트를 사용해 설치한다.

승격 및 실제 설치 전에는 digest를 다시 확인해 검사 대상과 실제 반입 대상의 동일성을 보장한다.

실제 설치 과정에서 검증 완료 세트에 없는 새로운 dependency를 외부에서 받아야 하는 경우에는 출처·버전·digest·서명·provenance를 확인하고 최소 검사를 수행한다. 이상 징후가 발견되거나 신뢰 근거가 충분하지 않으면 해당 dependency를 전체 검역 대상으로 되돌린다.

Package manager가 필요 없는 독립 binary나 archive는 동일성 검증 후 사용자가 지정한 위치로 직접 반입할 수 있다.

#### Staging Area 제약

| 제약 | 정책 |
| --- | --- |
| Artifact 실행 금지 | 설치·실행·분석을 수행하지 않고 보관과 전달만 수행 |
| 검사 완료 Artifact만 반입 | `ALLOW`된 Artifact와 dependency만 저장·반출 |
| 실제 Host 자산 접근 금지 | Host Secret, 프로젝트 파일, Credential 등 실제 자산을 노출하지 않음 |
| Artifact 변경 금지 | 검증 완료 후 가능한 한 immutable로 관리 |
| 외부 네트워크 접근 금지 | 인터넷 다운로드나 외부 통신을 수행하지 않음 |
| 검증 기록 동봉 | 버전, digest, 출처, dependency, 검사 결과와 evidence를 Artifact에 연결해 보관 |
| Digest 기반 동일성 유지 | staging 반입 시점과 사용자 환경 반출 시점에 digest를 재확인 |
